# Heyya v1.2 Assistant

## Flow
1. User sends any text message via `POST /rooms/:roomId/messages`
2. Route responds immediately with the saved message
3. `setImmediate` fires `processMessageIntent(content, roomId)` in background
4. `detectLeaveIntent` does quick keyword pre-filter, then calls GPT (`gpt-4o-mini`) with `response_format: json_object`
5. On match: `postConfirmationCard` inserts a `confirmation_card` message (senderId=null)
6. Frontend polls every 3s — picks up the card on next cycle
7. User taps "Confirm & Submit" → `POST /rooms/:roomId/assistant/confirm { confirmationMessageId }`
8. Route: creates leave record (approved immediately), marks card confirmed, posts system message, fires async Hook generation
9. Hook items generated by GPT scanning last 100 messages for assignment keywords

## Message types added
`confirmation_card`, `hook_card` — added to OpenAPI enum + codegen re-run

## OpenAI model
`gpt-4o-mini` — user owns their own OPENAI_API_KEY (Replit AI Integrations declined).

**Why:** setupReplitAIIntegrations returned `awaiting_phone_verification`; user chose to provide their own key.

## Hook card
- Renders full-width outside bubble (special case in MessageBubble before the bubble wrapper)
- Checkbox state persisted in localStorage keyed by `hook-{messageId}`
- Dismiss state persisted as `hook-{messageId}-dismissed`

## Confirmation card status
- `pending` → shows Confirm/Cancel buttons
- `confirmed` → shows green checkmark (buttons hidden)
- `cancelled` → shows grey cancelled state
- Status stored in message metadata; also reflected server-side on confirm/cancel

## UserAvatar null handling
`UserAvatar` returns null when `user` is undefined — safe for senderId=null assistant messages.
